## Changes

- Analyzer work, model discovery/checksum verification, reference embedding rebuild and video inference run in the existing background Task. Progress emissions are throttled to five per second per stage; the live preview queue remains single-item, and the existing sampled preview is limited to four updates per second and a maximum 960px width. The analyzer remains busy until the queued terminal callback and thread exit have been handled. Late preview events are discarded by scan state and project folder; progress events are ignored after terminal state. Cancellation restores the prior in-memory project and does not publish an intermediate analysis.json. Safe shutdown requests cooperative cancellation and prevents closing while work remains active.
- Stable group IDs are preserved through edits; a runner-up margin prevents ambiguous centroid assignments. Recent bounding-box overlap is used only to break ambiguous sampled-frame ties and marks the result uncertain; it does not establish identity or interpolate missing frames. Same-frame group reuse is prevented. Profile matching checks compatible normalized embeddings, absolute threshold, margin and consistency; overlapping candidate groups cannot both acquire a library identity. Filtered, ignored and uncertain groups are not automatically named.
- Rename, merge, split, ignore/restore, delete, solo, references and timeline seeking remain present. Merge and split clear stale identity metadata; the user must re-confirm the resulting identity. Invalid split indices are rejected. Restore toggles the filter override reversibly. Deleted groups do not delete source media or reference files. Timeline and preview share a deterministic group-ID color; active live groups are highlighted. The original manual extraction and other five tabs remain in place.
- Project JSON is staged with CSV/TXT before publication, with analysis.json authoritative and replaced last. Unique temporary files are cleaned on error. UI reports save failures instead of announcing success. V2/V2.2 project opening preserves unknown JSON fields and does not rewrite existing files simply by opening them. Source media is read-only in this workflow.
- Encrypted People Library references and embedding caches are reused. Model signatures and reference fingerprints invalidate incompatible/stale vectors. Reference-only profiles are rebuilt locally using the same engine as video analysis; ambiguous, missing and invalid reference images are not treated as confirmed. Unreadable encrypted caches are preserved and warnings recorded. Saving requires manual confirmation or a library match, deduplicates reference digests and does not silently merge identities merely because names match. Settings includes explicit non-destructive import for V2.2 People_Library/<id>/profile.json with an explicit name and reference image files. Imports copy into the encrypted store; original files and old vectors are not modified. Name collisions are skipped; unknown schema is not guessed.
- Default model discovery searches configured paths, standard Clipivo/InsightFace caches and LOCALAPPDATA/Programs/Clipivo/_internal without hardcoded account names. Unverified copies are skipped; missing verified weights are downloaded only to the app data cache. Both default weights use the sizes and SHA-256 digests already pinned in core/downloads.py and V2.2 model_locator.py. Download cancellation is checked before publication and partial files cleaned. Default InsightFace non-commercial research notice and explicit acceptance remain; separately licensed compatible custom SCRFD/ArcFace model folders are explicit, fingerprinted, and not silently replaced by defaults. Settings validates a chosen default folder before assigning it to the original extractor. GPU initialization failures, mixed session providers and inference exceptions fall back to CPU; both ONNX sessions must report the requested provider before it is shown as selected.
- Live statistics report measured decoded/sample counts, elapsed time, sampled analysis FPS, estimated ETA/progress, realtime speed, system CPU percentage and process RSS. Completion reports measured analysis timing and the selected provider; GPU utilization is not fabricated. Sampled timestamps remain estimates.
- Analyzer-to-extractor handoff excludes ignored/filtered/empty ranges, unions overlaps before applying clip limits, binds the request to the actual source/probe and discards a failed/stale probe request. An existing extractor range list is replaced only with explicit confirmation. No picker, footage, render, replacement page, core/export or CapCut files were edited.

## Unresolved limitations and acceptance work

1. Native Windows/PySide6 startup, interactive UI race and manual operation acceptance still required. Use the original six tabs and exercise a real long analysis, cancel during download and inference, close while scanning, reopen V2.2 and V2.3, rename, merge, split, ignore/restore, solo, delete, save and reselect profile, seek references/timeline and transfer ranges to an already populated extractor. Actual GPU/CPU inference, CUDA/DirectML fallback and model reuse on the target machine require real tests. Cooperative cancellation cannot instantly interrupt a blocking native inference call or HTTP read; the application must stay open until the worker stops.
2. Grouping, cosine thresholds and spatial tie-break are provisional heuristics, not calibrated face identity confidence. Full between-sample tracking, scene-boundary/exact-frame refinement and production identity-quality benchmarking remain pending. Live summaries recompute group data; long-video memory and responsiveness need measurement.
3. V2.2 flat profile import supports the documented directory and explicit name field; other legacy schema variants and real user profile folders have not been tested. Same-name legacy profiles intentionally require manual review rather than implicit merge. Large explicit imports may take time on the GUI thread. Project observations and crops remain local plaintext as in V2.2; encrypted library storage does not imply project encryption. Failed/cancelled runs may leave partial crop directories without completed JSON. Simultaneous external application instances and Windows keyring acceptance remain unverified. CSV/TXT are sidecars, not a multi-file transactional database; if a filesystem replacement fails during publication, regenerate sidecars from the authoritative JSON.
4. No full-source clone or Windows runtime could be used in this environment; do not treat the partial portable test run as release certification. No build workflow or EXE creation was authorized or attempted.
