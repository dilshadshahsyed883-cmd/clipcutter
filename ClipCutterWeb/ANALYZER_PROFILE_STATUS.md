# Person Analyzer reference-set integration

Source checkpoint: authorized, explicitly supplied reference image sets can be saved under a manual label, reused in later Analyzer requests, and deleted from the owner's private SQLite ledger. Verification uses SHA256, size, supported image signatures, immutable snapshots, no automatic name merging, owner isolation and CSRF. Limits: 12 images, 16 MiB per image, 64 MiB per set, 100 sets and 512 MiB total reference content. No model vectors or crops are stored in the profile library. Reference images remain sensitive; owner-only storage is not encryption at rest. Delete removes the reusable set and prevents new selection; prior job copies and backups are retained, and unfinished intake blocks deletion.

One selected reference set or Drive reference link is accepted per analyzer request. Actual worker Staged contract validates the manifest; worker verifies each input and re-derives model features for the current packaged model. The selected set comparison uses desktop consistency thresholds and refuses inconsistent or overlapping candidates, with anonymous output labels and explicit review required. No raw vectors, crops or external identity lookup in results. A fully equivalent desktop People Library (save detected group crops, multi-profile review/edit/merge/split, encrypted storage, per-project retention/deletion) remains unimplemented. This is a deliberately bounded reference-set workflow, not full desktop parity. Physical GPU/model licensing/supply, Drive output delivery, cancellation/recovery, and final image approval remain pending. No image build or live operations.
