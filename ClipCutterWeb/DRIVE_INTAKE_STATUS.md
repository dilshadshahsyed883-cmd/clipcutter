# Drive intake only — candidate

Separate read-only Unix socket service, using the existing canonical Scene rclone identity, not the existing Concat socket. No credential copy, no change to Concat, no upload/write/delete or GPU dispatch. Source covers single video, ZIP and recursive video folders plus image files/folders. Supported input suffixes and basic container signatures are checked; actual decode/ZIP contents are not verified until later worker validation. Folder downloads compare Drive size and MD5; direct links rely on rclone transfer and bridge/client size and SHA256/MD5. No remote metadata is fabricated for direct links. Input is staged under private owner inputs/<job>/ with manifest and atomic promotion. Five transient attempts at 20-second intervals, maximum 4 GiB per file, 20 GiB per job, 200 files, 5 GB disk reserve. Progress counts verified files, not simulated bytes.

This candidate uses explicit Download input after Save request, and Retry intake for interrupted/failed staging; no automatic queue scheduler, in-flight cancellation, or GPU start in this phase. The capability endpoint checks bridge protocol and configured rclone remote name, not actual permission to every source. Health can be unavailable while a transfer is running because bridge concurrency is one. Direct links with unsupported extensions are rejected. The bridge has no path-by-name fallback for resource-key-restricted folder children. ZIP intake checks the archive directory, not extracted contents.

## Host activation (not performed)

A separate root-managed service must run deploy/drive_intake_bridge.py as the existing canonical Scene Drive identity with its existing rclone environment and HOME (do not copy credentials). Use independent directories /run/clipcutter-drive-bridge and /var/lib/clipcutter-drive-bridge, separate from Concat. Create a dedicated bridge group; allow only Scene identity and clipcutterweb access to socket directory, and only Scene identity access to private spool. Ensure the bridge process can chgrp to the dedicated group and that the client UID is clipcutterweb. Install script in root-owned immutable location readable by Scene. Example arguments: --socket /run/clipcutter-drive-bridge/intake.sock --spool /var/lib/clipcutter-drive-bridge --remote gdrive --client-user clipcutterweb --client-group clipcutter-drive-bridge. Verify actual remote and identity on VPS; gdrive is only the canonical default. Use a dedicated systemd unit with UMask=0077, private spool, no privilege escalation, and no modifications to Concat. CLIPCUTTER_DRIVE_BRIDGE_SOCKET defaults to the above socket. Host activation, credentials/access, rclone transfer behavior and real-file tests require manual VPS verification before production. Never start paid resources for this intake-only phase.
