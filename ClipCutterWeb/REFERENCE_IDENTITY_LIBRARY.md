# Reference identity library and output names

- Clip Extractor defaults to Identity Library. Existing PC and Drive reference entry remain available; manual whole-picture A/B may run without identity. Select a saved identity for identity-based output names. Library images are private to the signed-in owner; at most 12 images per identity, 10 MiB each, JPG/PNG/WEBP. Bulk PC uploads use the existing scoped 128 MiB request endpoint; Drive imports use the read-only bridge. Rename, replace, delete, select all and cancel uploads operate inside the in-app dialog.
- The identity ID, label, prefix and verified reference image copies are snapshotted when saving a request; batch children inherit the same snapshot. Changes to the library do not change previously queued jobs. Deletion is a tombstone; storage cleanup is deliberately not automatic.
- Verified GPU artifacts remain immutable internally. VPS allocates identity counter numbers in a transaction after verified receipt, before Drive delivery. Names are `Alex_Eala_001.mp4` / `Alex_Eala_Stitched_002.mp4`; counters continue across jobs and renames; reserved names are never reused. Direct PC/Drive requests without a selected identity retain existing generic names. Drive destination uses the display name for identity jobs, with existing immutable/no-overwrite checks. No changes to the GPU image or runtime contract.
- Output controls filter completed jobs by identity, preview and download, show verified clip durations if supplied, rename or hide clips only after acknowledged GPU receipt, bulk select/delete and download selected ZIP (2 GiB cap plus storage reserve). Rename/delete are local display metadata changes, not physical deletion or modification of delivered Drive files. Existing Drive delivery credentials and activation still required. Separate source-named Drive subfolders and live browser/Drive acceptance are not implemented by this change.
