# Verified batch source integration

Drive folders and ZIP files expand on the VPS before any GPU child is eligible. The original batch is retained, and each video gets a separate immutable staged input manifest and deterministic child ID. Shared reference images are copied and verified per child; child processing uses the existing single-video protocol (including explicit scan review). ZIP member names never become extraction paths; all entries are streamed through CRC checks, bounded total size and count, and supported videos undergo format checks. All children are committed atomically only after every source is verified. Parent batch_expanded is nonprocessing; child states determine queue and idle behavior. Batch members API/UI links to each child's review and verified outputs.

Limits: 200 videos, 4 GiB per source video, 20 GiB total expanded input and reference copies, 12 references up to 16 MiB each, 5 GB free disk reserve. The original verified batch is kept, so sufficient duplicate storage is required. ZIP child source URL is archive provenance, not a new download instruction. No cross-video identity merge, no aggregate stitched output. Actual runtime and GPU testing remain pending. Drive output delivery, analyzer profiles, cancellation/reconciliation and authorized model packaging remain blockers; do not enable live scheduler or build final image yet.
