# Scheduler/UI source checkpoint

Separate scheduler entry point and optional systemd service source added; not installed or started. One approved owner, group, private digest, gateway and worker SHA required. Explicit scheduler/lifecycle enable flags remain unset. Cross-process scheduler lock plus owner admission lock serialize new request creation, retry-intake entry and scheduler decisions. Scheduler runs Drive intake in one independent thread, monitors the durable GPU attempt before new dispatch, stops new dispatch while paused and reconciles running/delivery work. Authenticated admin/CSRF-protected start/stop/pause/resume/recheck UI writes durable commands only when the approved scheduler is online. Retry does not erase ambiguous operation journals. Configuration changes require restart, not retargeting.

Source is not runtime acceptance. ZIP/folder expansion, reference scan review/export continuation, analyzer profiles, Drive output upload, cancellation/reconciliation for staged attempts (including paused/stopping with unfinished uploads), full format and disk checks, actual model rights/files and private image finalization remain blockers. Unsupported ZIP/folder, analyzer profile or Drive-output requests are retained locally and explicitly failed before automatic dispatch. Review attempts remain protected pending continuation. Do not deploy or activate live scheduler before remaining gates pass. No Docker build, paid GPU start or VPS changes.
