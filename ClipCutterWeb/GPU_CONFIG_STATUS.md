# GPU Config implementation checkpoint

The third Studio tab now has a real owner-scoped settings API, private SQLite persistence, administrator and CSRF checks, write-only credentials, Concat threshold and timer defaults, and explicit real read-only SaladCloud status with normalized pulling progress. Blank credentials retain saved values; the remove option removes database values, not root environment fallback credentials. Credentials are kept in the existing mode-0600 service database and private backups; never return them in API responses. No external endpoint other than the fixed Salad management HTTPS API is contacted.

This is not full GPU orchestration. The candidate worker in PR #6 advertises dispatch_enabled=false and supports staged-local CLI only. Its CI was pending at inspection. Drive intake, remote submission and result receipt, profile retention/deletion, durable job and lifecycle scheduler, Start/Stop/Retry and automatic reallocation are not implemented. Mutating Salad operations are blocked intentionally. The saved automatic mode is a preference, not an active automation. Concurrency 2 requires actual worker acceptance. Do not deploy a candidate image or claim production readiness on the basis of this UI. Follow GPU_CONFIG_RULES.md for the remaining integration.

Added source regression tests for defaults, progress normalization, validation, fixed-origin read-only status, authentication, CSRF, private owner settings, and disabled mutations. Full pinned suite and browser tests must pass before merging this implementation. No EXE build, live API request, VPS deployment or Concat change was performed.
